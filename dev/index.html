LAIR: Land-Air Interactions Research#

lair is a collection of tools that I have developed/acquired for my research regarding land-air interactions. It is designed to make it easier to work with atmospheric data: meteorological calculations, emissions inventories, NOAA greenhouse-gas products, soundings, HRRR winds, background estimation, mobile transects, geospatial helpers, and plotting.

New to lair? Install it (below), then start with the Quickstart.

Installation#

lair is installed from GitHub, not from PyPI. On PyPI, lair is an unrelated project (a helper for Flask web services), so pip install lair installs the wrong package.

You need Python 3.11 or newer and git (pip uses git to download the code). Install lair into a new environment, so that its packages stay apart from the rest of your work.

The commands on this page were run on 64-bit Linux. lair’s own tests also run on macOS and Windows, without the extras.

Pick a route#

Grid-cell areas (geo.gridcell_area) and regridding (geo.regrid, geo.resample) need ESMF, a compiled library that pip cannot install. The inventories use both, so Inventory.integrate() (the total of an inventory over a region) and Inventory.absolute_emissions need ESMF too.

  • To use the inventories or to regrid, use conda.

  • For everything else, pip is enough.

conda (everything)#

conda is a package manager. It installs Python itself, and compiled libraries such as ESMF, into separate environments. mamba is a faster command with the same arguments. Both come with Miniforge.

mamba create -n lair -c conda-forge python=3.12 esmpy "esmf=*=nompi*"
conda activate lair
pip install "lair[complete] @ git+https://github.com/jmineau/lair.git"

The first line makes an environment named lair with Python and ESMF. It asks for the no-MPI build of ESMF: lair does not use MPI, and the MPI build can print errors when it starts on a machine where MPI is not set up (this happened on a compute node of a cluster). lair is not on conda-forge, so the last line uses pip. It installs lair and every extra (see Optional dependencies).

pip (everything except ESMF)#

venv comes with Python. It makes a folder that holds a private copy of the packages you install.

python3 -m venv lair-env
source lair-env/bin/activate
pip install "lair[requests,formats,geo,science] @ git+https://github.com/jmineau/lair.git"

If python3 --version shows less than 3.11, use python3.12 (or another version you have) in the first line. On Windows, activate with lair-env\Scripts\activate.

uv does the same job as venv and pip, faster, and can fetch the Python version for you:

uv venv --python 3.12 lair-env
source lair-env/bin/activate
uv pip install "lair[requests,formats,geo,science] @ git+https://github.com/jmineau/lair.git"

lair[complete] also installs with pip, but import xesmf then fails with No module named 'ESMF', and so do the functions listed above.

A release, or no git#

To install a release instead of the newest code, add @ and its tag to the address (the tags are on the Releases page):

pip install "lair[geo,science] @ git+https://github.com/jmineau/lair.git@v2026.12.8"

If git is not installed, pip can install from a zip of the repository instead:

pip install "lair[geo,science] @ https://github.com/jmineau/lair/archive/refs/heads/main.zip"

From a clone of the repository, pixi builds an environment with every extra, ESMF included, from pixi.lock (pixi install; 64-bit Linux only). To change lair’s code, see CONTRIBUTING.md.

Check the install#

python -c "import lair; print(lair.__version__)"

This prints the version, for example 2026.12.8. The first import in a new environment also downloads a file; the next section says which.

The first import downloads a file#

lair.background uses the CCG filter, curve-fitting code that NOAA’s Global Monitoring Laboratory publishes. It is not part of lair’s repository. The first time you import lair in an environment, lair downloads NOAA’s ccg_filter.zip from ftp.gml.noaa.gov and saves ccg_filter.py from it as _ccg_filter.py inside the installed lair folder. Each environment downloads it once. The filter also needs scipy (the science extra).

Only lair.background uses the file. Without it, the rest of lair works as usual. There are three ways to be without it:

  • No network. import lair still works. It logs a warning, Could not install NOAA's CCG filter (...). lair.background is unavailable until lair.setup_ccg_filter() succeeds., and import lair.background raises an ImportError that says the filter is not installed. The next import lair tries the download again.

  • Skip the download. Set LAIR_SKIP_CCG_DOWNLOAD before importing, for example in a script that runs offline:

    export LAIR_SKIP_CCG_DOWNLOAD=1

    Any text counts, including 0. An empty value does not.

  • Place the file yourself, for example when your network allows HTTPS but not FTP. NOAA serves the same zip over HTTPS. The last two lines copy the file into the installed lair folder (this does not import lair):

    curl -O https://gml.noaa.gov/aftp/user/thoning/ccgcrv/ccg_filter.zip
python -m zipfile -e ccg_filter.zip ccg_filter
LAIR_DIR=$(python -c "import importlib.util as u, os; print(os.path.dirname(u.find_spec('lair').origin))")
cp ccg_filter/ccg_filter.py "$LAIR_DIR/_ccg_filter.py"

On CHPC (University of Utah)#

The steps above work on CHPC’s general-environment clusters (tested on Notchpeak), on a login node or in a job: compute nodes can reach GitHub, PyPI and NOAA. Use conda, which CHPC provides as the miniforge3 module:

module load miniforge3
mamba create -n lair -c conda-forge python=3.12 esmpy "esmf=*=nompi*"
conda activate lair
pip install "lair[complete] @ git+https://github.com/jmineau/lair.git"

  • python3 on CHPC is Python 3.6, too old for lair. The environment brings its own Python.

  • Run module load miniforge3 in every new shell and in every job script before conda activate lair. CHPC advises against loading it automatically at login, because that breaks remote desktop sessions (FastX and OnDemand). See CHPC’s Python and Anaconda page.

  • mamba create may print two Could not open lockfile errors. They come from the shared module, and the environment is made anyway.

  • The environment is about 1.3 GB and goes in ~/.conda/envs, which counts against your home directory’s quota. To put it elsewhere, use mamba create -p /path/to/lair-env ... and conda activate /path/to/lair-env.

  • For a lighter environment without ESMF (about 0.6 GB), run module load uv and then the uv commands above. pixi is not a CHPC module.

  • Your group may already keep copies of the data (see Data locations). Ask where, and point the LAIR_* variables at them.

import cartopy prints a PROJ error#

In an environment built as above, import cartopy prints nothing. In a conda-forge environment that also has fiona (cartopy loads it when it is there), you may see

ERROR 1: PROJ: proj_create_from_database: Open of /path/to/env/share/proj failed

when you run that environment’s python without activating the environment: by its full path, from a job script, or in a notebook kernel. The message comes from GDAL, which fiona loads, and it is harmless: coordinates transform to the same numbers with and without it. conda activate removes it. Without activating, set PROJ_DATA to the environment’s share/proj folder.

Logging#

lair logs through Python’s standard logging module, under the lair logger (one child logger per module, e.g. lair.records). Warnings are shown by default; progress messages are logged at INFO and hidden unless you ask for them:

import logging
logging.basicConfig(level=logging.INFO)            # everything, incl. lair
logging.getLogger("lair").setLevel(logging.INFO)   # or tune lair alone

lair.background.thoning_filter prints the CCG filter’s diagnostics when the lair.background logger is at DEBUG.
